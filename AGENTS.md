# SQL Data Mover

GUI-приложение на C# (.NET 10, Avalonia UI) для копирования данных с одного SQL-сервера на другой. Пока поддерживается MS SQL Server, архитектура рассчитана на добавление других СУБД.

## Сборка и запуск

```bash
dotnet build SqlDataMover.slnx        # сборка решения (SDK 10+; формат решения .slnx)
dotnet run --project src/SqlDataMover.App    # запуск приложения
dotnet test tests/SqlDataMover.Core.Tests    # тесты ядра
```

Требуется установленный .NET SDK 10. Приложение кроссплатформенное (Avalonia).

## Как работает копирование (DataCopyEngine)

1. Для каждой выбранной таблицы загружаются метаданные из источника и приёмника.
2. Таблицы сортируются по внешним ключам: родители раньше детей (циклы → ошибка).
3. Для каждой таблицы в порядке сортировки, в одной транзакции на таблицу:
   - в приёмнике загружается словарь «комбинация значений полей сопоставления → целевой ID»
     (целевой ID = identity, иначе PK, иначе первое поле сопоставления);
   - строки источника читаются потоково (IAsyncEnumerable) пакетами (до 1500 параметров SQL);
   - строка, найденная в приёмнике по всем полям сопоставления → UPDATE остальных колонок
     (кроме полей сопоставления, PK и identity), её целевой ID попадает в сопоставление;
   - не найденная строка → INSERT без identity-колонки; новый ID возвращается через
     `OUTPUT INSERTED.[col]` и попадает в сопоставление;
   - если identity-колонка приёмника выбрана полем сопоставления, значения identity
     копируются из источника как есть: на время вставки включается `SET IDENTITY_INSERT`
     (иначе identity назначается приёмником, см. предыдущий пункт);
   - после копирования таблицы с identity-полем сопоставления счётчик identity приёмника
     выравнивается по источнику (`DBCC CHECKIDENT ... RESEED` по `IDENT_CURRENT` источника),
     чтобы последующие автогенерируемые ID совпадали;
   - сопоставление «оригинальный ID → новый ID» ведётся по колонкам, на которые ссылаются
     внешние ключи других выбранных таблиц (см. ComputeReferencedColumns);
   - при чтении дочерней таблицы значения FK подставляются из сопоставления.
4. Самоссылающиеся FK (Employees.ManagerId) обрабатываются двухфазно: при вставке
   значение ставится в NULL (если родитель ещё не обработан), после обработки всех строк
   таблицы выполняется `UPDATE ... SET fk = mapped WHERE <mappedCol> = <newId>`.

Ссылки на невыбранные таблицы не подставляются: значения FK копируются как есть
(предполагается, что они уже есть в приёмнике).

### Режим предпросмотра (CopySettings.DryRun)

Шаг 4 мастера («Предпросмотр») запускает движок с `DryRun = true`: строки источника
читаются и сопоставляются как при обычном копировании, но запись не выполняется —
транзакция не открывается, INSERT/UPDATE/фаза 2 пропускаются. Итог — по каждой таблице
сколько строк было бы вставлено и обновлено (и ошибки, если они возникли бы). Вместо
новых identity подставляются отрицательные фиктивные ID, чтобы корректно разрешать FK
дочерних таблиц и предсказывать ошибки «Нет сопоставления ID»; счётчики при этом
совпадают с реальным прогоном. Число строк по таблицам из предпросмотра используется
как знаменатель для детерминированного процента прогресса при реальном копировании
(префиксные суммы завершённых таблиц + обработанные строки текущей).

### Опция CopySettings.AllowTemporaryUniqueDuplicates (чекбокс на шаге 4)

Для таблиц с уникальными полями в процессе копирования может возникнуть транзиентное
задвоение значения (новая строка вставляется со значением, которое ещё не освободила
обновляемая устаревшая строка) — INSERT роняет уникальный индекс приёмника. Опция
отключает уникальные индексы приёмника (кроме PK, см. `IDbProvider.GetUniqueIndexesAsync`
и `SetUniqueIndexEnabledAsync`) на время копирования каждой таблицы и пересоздаёт их
(`REBUILD`) перед коммитом — внутри той же per-table транзакции, поэтому при ошибке
откат возвращает индексы во включённое состояние. Реальные дубликаты, оставшиеся к концу,
ронят REBUILD, и транзакция таблицы откатывается. В MSSQL реализовано через
`ALTER INDEX ... DISABLE / REBUILD` (для UNIQUE-ограничений `NOCHECK` не действует);
требует прав ALTER на таблицы приёмника. В dry run индексы не трогаются.

### Опция CopySettings.DeleteExtraRows (чекбокс на шаге 4)

«С удалением лишних записей в таблицах-получателях»: строки приёмника, комбинация значений
полей сопоставления которых отсутствует в источнике, удаляются ДО вставки/обновления —
устаревшие строки освобождают значения identity и уникальных полей, и вставка не конфликтует.
Отдельный проход (когда опция включена) выполняется до основного цикла копирования,
в обратном топологическом порядке — дети раньше родителей, иначе внешний ключ не позволит
удалить родителя, на которого ещё ссылаются дети. Каждый проход по таблице — в своей
per-table транзакции с commit; ошибка таблицы обрабатывается как обычно (см. ContinueOnTableError).
Лишние строки определяются по полям сопоставления: читаются ключи источника (только поля
сопоставления), загружается целевой словарь `LoadMatchMapAsync`, удаляются ключи, которых
нет в источнике, через `IDbProvider.DeleteRowsAsync` (DELETE по AND-комбинации полей,
в SQL Server — пакетами до 1500 параметров). Строки с NULL в любом поле сопоставления
не сопоставляются и не удаляются. В dry run проход выполняется без записи и только считает
строки к удалению (счётчики совпадают с реальным прогоном); результат пишется в
`TableCopyResult.Deleted` и показывается в предпросмотре колонкой «Удалено» и в сводках.

## Семантика сопоставления по полям

Пользователь отмечает для каждой таблицы одно или несколько полей сопоставления
(по умолчанию — все колонки PK, если они есть; иначе первая колонка). Комбинация их значений —
ключ сопоставления, может не совпадать с PK. Совпадение по всем полям → обновление
существующей строки, отсутствие → вставка. Если в любом поле ключа NULL, строка всегда
вставляется. Ключи сравниваются без учёта регистра (CompositeKey поверх ObjectKeyComparer),
как стандартная коллация SQL Server.

Полем сопоставления может быть и identity-колонка. В этом случае значения identity
копируются из источника как есть (включается `SET IDENTITY_INSERT`), а после копирования
счётчик identity приёмника выравнивается по источнику.

## Добавление новой СУБД

1. Реализовать `IDbProvider` (метаданные, потоковое чтение, вставка с возвратом identity,
   `SetIdentityInsertAsync`, `GetIdentityCurrentAsync`, `ReseedIdentityAsync`, обновление
   и удаление по полям сопоставления, транзакции).
2. Добавить `ProviderDescriptor` и ветку в `DbProviderFactory.Create`.

## Ограничения и особенности

- Целевые таблицы должны существовать; схема (колонки) не создаётся и не мигрируется.
- Копируются только общие колонки; вычисляемые и identity приёмника пропускаются
  (identity копируется как есть, только если выбрано полем сопоставления).
- Если комбинация полей сопоставления не уникальна в источнике, последняя строка «побеждает».
- Самоссылающаяся таблица с NOT NULL FK: строка-ребёнок, встреченная раньше родителя,
  вызовет ошибку вставки (NULL), если у FK нет значения для подстановки.
- FK, ссылающийся на не-PK уникальную колонку при наличии identity, маппится по identity
  колонке (редкий случай — результат может быть неверным).
- `OUTPUT INSERTED` не работает с триггерами INSTEAD OF на таблице приёмника.
- Строки читаются и маппятся в памяти: объём сопоставлений ~ число строк выбранных таблиц.
- При подключении к MSSQL по умолчанию добавляется `Encrypt=Optional` и
  `TrustServerCertificate=True`, если они не заданы в строке подключения.
- Счётчик строк в дереве таблиц — приблизительный (sys.partitions).

## Тесты

`tests/SqlDataMover.Core.Tests`:

- TableDependencySorterTests — порядок, самоссылки, циклы, внешние зависимости;
- IdMappingStoreTests — сопоставление и сравнение ключей;
- CompositeKeyTests — составной ключ: равенство, порядок компонентов, регистр, NULL, хэши;
- DataCopyEngineTests — сквозная проверка движка на FakeProvider: переназначение identity,
  подстановка FK, сопоставление по не-PK полю и по составному ключу с обновлением (включая
  регистронезависимость, таблицы без identity/PK, FK по обновлённым строкам), самоссылки,
  порядок таблиц, ошибки конфигурации и отсутствия сопоставления; режим предпросмотра
  (DryRun): счётчики без записи, совпадение счётчиков с реальным прогоном, самоссылки
  и ошибки в предпросмотре; сохранение identity как есть, когда identity-колонка выбрана
  полем сопоставления (вставка значений без переназначения + выравнивание счётчика приёмника
  по источнику в реальном прогоне и в предпросмотре); удаление лишних строк приёмника
  (DeleteExtraRows): только с опцией, дети раньше родителей, без записи в предпросмотре,
  совпадение счётчиков предпросмотра и реального прогона.
- SqlServerIntegrationTests — сквозной тест против локального SQL Server (строки подключения
  захардкожены, `localhost`): сначала выполнить tests/sql/setup-test-databases.sql. Проверяет
  реальный SqlServerProvider: составное сопоставление, переназначение identity, FK-цепочку
  Customers → Orders → OrderItems, самоссылающуюся Employees и выравнивание счётчика identity
  по источнику для таблиц с identity-полем сопоставления; удаление лишних строк с FK-порядком
  (дети раньше родителей).

`tests/SqlDataMover.App.Tests` (GUI, xunit v3):

- MainViewModelTests — полный сценарий мастера на ViewModel: блокировка «Далее/Назад»,
  подключение через fake-провайдер, выбор таблиц, сопоставление по умолчанию (PK),
  предпросмотр (dry run) со счётчиками вставки/обновления, ошибка подключения.
  Провайдер регистрируется через `DbProviderFactory.Register` (ключ уникален на тест).
- MainWindowTests — headless UI (Avalonia.Headless.XUnit, `UseSkia` + `UseHeadlessDrawing=false`):
  реальное окно, клики по кнопкам, ввод в поля подключения, биндинги, навигация по всем
  шагам, вывод ошибки подключения, рендер кадра (`CaptureRenderedFrame`).
- Особенности headless-тестов: контролы страниц ищутся по визуальному дереву (у страниц свой
  namescope); перед кликом прогоняются отложенные задачи layout, иначе координаты устаревают;
  настройки (`AppSettingsStore.FilePath`) перенаправляются во временный файл, чтобы не трогать
  реальный `%APPDATA%`.

Тестируемость в самом коде: `DbProviderFactory.Register` (тестовые СУБД), переопределяемый
путь `AppSettingsStore.FilePath`, `x:Name` на ключевых контролах окна и страниц.
